# เช็กอินกิจกรรม: เหตุผลของการออกแบบ

เอกสารนี้อธิบายว่าแต่ละฟีเจอร์และฟังก์ชัน "มีไว้ทำไม" ใช้ตอบคำถามตอนสาธิตได้

## ปัญหาและผู้ใช้

- **ผู้ใช้:** นักศึกษาที่ต้องเข้าร่วมกิจกรรมให้ครบตามที่มหาวิทยาลัยกำหนด (ข้อมูลตัวอย่างใช้พิกัดมหาวิทยาลัยขอนแก่น วิทยาเขตหนองคาย)
- **ปัญหา:** ไม่รู้ว่ามีกิจกรรมอะไร ลืมวันงาน การเช็กชื่อกระดาษเซ็นแทนกันได้ และนักศึกษาไม่มีหลักฐานในมือถ้าชื่อตกหล่น
- **เส้นทางหลัก:** ค้นหา → บันทึกไว้ / ลงทะเบียน → แจ้งเตือนเมื่อเปิดเช็กอิน → ไปถึงงาน → ตรวจตำแหน่ง + ถ่ายรูป → จำนวนกิจกรรมเพิ่ม

## ข้อมูลหลัก (`src/types/models.ts`)

| ข้อมูล | เหตุผล |
|---|---|
| `Activity.location.radiusM` | แต่ละสถานที่ใหญ่ไม่เท่ากัน (ห้องประชุม 120 ม. / แปลงป่า 300 ม.) รัศมีเช็กอินจึงต้องกำหนดรายกิจกรรม |
| `Activity.checkInMethod: 'app' \| 'paper'` | หลายกิจกรรมยังใช้ใบเซ็นชื่อ แอปต้องรองรับทั้งสองแบบ |
| `Registration.status` มี `pending_review` | รูปใบเซ็นชื่อต้องให้คนตรวจ แอปอ่านลายเซ็นเองไม่ได้ ห้ามนับทันที |
| `CheckInRecord.takenAt` แยกจาก `submittedAt` | ถ่ายตอนออฟไลน์แล้วส่งทีหลังได้ server ตรวจเวลาจากตอนถ่าย |

## สัปดาห์ 6 · REST API (`server/`, `src/services/`)

| ฟีเจอร์ | เหตุผล |
|---|---|
| server กลางใน repo (Node.js ล้วน) | ที่นั่งต้องตรงกันทุกคน ผลเช็กอินต้องเก็บที่ผู้จัดตรวจได้ และ clone แล้วรันได้โดยไม่ต้องติดตั้งอะไรเพิ่ม |
| `apiRequest` จุดเดียวที่เรียก fetch | ตรวจ `response.ok` ทุกครั้ง, timeout, ยกเลิก request ได้ หน้าจอไม่เรียก fetch เอง |
| `validators.ts` ตรวจ JSON ตอนรัน | TypeScript ตรวจได้แค่ตอน compile ข้อมูลจากเครือข่ายอาจผิดรูปแบบ |
| 409 เมื่อเต็ม / ลงซ้ำ | server ตัดสินสุดท้าย แม้หน้าแอปจะแสดงว่ายังมีที่ |
| Idempotency-Key | เน็ตหลุดแล้วกดส่งใหม่ จะไม่ได้การลงทะเบียน 2 รายการ |
| server ตรวจระยะทาง/เวลา/รูป JPEG ซ้ำ | ค่าจากแอปถูกแก้ไขได้ |
| ข้อความ login ผิดแบบเดียวกันทุกกรณี | ไม่บอกว่ารหัสนักศึกษาไหนมีอยู่ในระบบ |
| หา IP ของ API อัตโนมัติ (`api-config.ts`) | clone แล้ว `npm start` ใช้ได้ทันที ไม่ต้องสร้าง `.env` |

## สัปดาห์ 7 · Storage และ Offline (`src/storage/`)

| ข้อมูล | ที่เก็บ | เหตุผล |
|---|---|---|
| รายการบันทึกไว้, cache กิจกรรม | AsyncStorage | ข้อมูลเล็ก ไม่ลับ |
| token | SecureStore | มีค่าเท่ารหัสผ่าน |
| การลงทะเบียนของฉัน, คิวเช็กอิน | SQLite | เป็นตาราง ลบ/อัปเดตทีละแถว รูปในคิวมีขนาดใหญ่ |

| ฟีเจอร์ | เหตุผล |
|---|---|
| แสดง cache ก่อน แล้วค่อยโหลดจาก server | เปิดแอปแล้วไม่เจอหน้าว่าง |
| แถบ "ออฟไลน์ · ข้อมูลล่าสุดเมื่อ…" | ต้องบอกว่ากำลังดูข้อมูลเก่า |
| **คิวเช็กอินออฟไลน์** | หอประชุมสัญญาณมักไม่ดี นักศึกษาอยู่ในงานจริงแต่ส่งไม่ได้ จึงเก็บไว้ก่อนแล้วส่งอัตโนมัติ |
| อ่านข้อมูลเสียแล้วไม่ crash (`readJson`) | ถ้า cache พังให้เริ่มจากค่าว่าง ดีกว่าเปิดแอปไม่ขึ้น |
| key มีเวอร์ชัน (`/v1`) | ถ้ารูปแบบข้อมูลเปลี่ยนภายหลัง จะย้ายข้อมูลเก่าได้ |
| เว็บใช้ไฟล์ `.web.ts` | SQLite/SecureStore ไม่มีบนเว็บ หน้าจอไม่ต้องรู้ว่าข้างหลังใช้อะไร |

| ฟีเจอร์ | เหตุผล |

| Logout ล้าง token, cache, คิว, แจ้งเตือน | เครื่องอาจใช้ร่วมกัน |

## สัปดาห์ 9 · กล้อง (`src/app/check-in/[registrationId].tsx`)

| ฟีเจอร์ | เหตุผล |
|---|---|
| **ถ่ายสด หรือเลือกจากคลังรูป** | เลือกจากคลังได้เผื่อถ่ายไว้แล้วตอนอยู่ในงาน หรือกล้องในแอปเปิดไม่ได้ |
| **รูปจากคลังต้องมีเวลาถ่าย (EXIF) อยู่ในช่วงงาน** | กันการใช้รูปเก่าหรือรูปที่เพื่อนส่งมา (แอปแชตลบ EXIF ทิ้ง จึงใช้ไม่ได้) ตรวจทั้งในแอปและที่ server |
| **บันทึกว่ารูปมาจากคลัง** | ผู้จัดเห็นว่ารูปไหนไม่ได้ถ่ายสด ตรวจละเอียดขึ้นได้ |
| **บนเว็บถ่ายสดอย่างเดียว** | เบราว์เซอร์ไม่ส่ง EXIF มา จึงตรวจเวลาถ่ายไม่ได้ |
| **โหมดสาธิต: ใช้รูปที่ไม่ผ่านเป็น "รูปทดสอบ"** | สาธิตการส่งรูปได้โดยไม่ต้องไปอยู่ในงานจริง แสดงเฉพาะตอนพัฒนา (__DEV__) server รับเฉพาะ demo mode และบันทึกที่มาว่าเป็นรูปทดสอบ |
| เซลฟี่ (กล้องหน้า) สำหรับเช็กอินในแอป | เห็นทั้งตัวคนและบรรยากาศงาน |
| รูปใบเซ็นชื่อ (กล้องหลัง) สำหรับงานที่ใช้กระดาษ | นักศึกษามีหลักฐานในมือ ถ้าชื่อตกหล่นก็พิสูจน์ได้ |
| ขอสิทธิ์ตอนกดเปิดกล้อง + อธิบายเหตุผล | ผู้ใช้เข้าใจว่าขอไปทำอะไร |
| ปฏิเสธถาวร → ปุ่มเปิด Settings | บอกวิธีแก้ ไม่ใช่แค่ขึ้น error |
| ดูรูปก่อนส่ง / ถ่ายใหม่ | รูปเบลอถ่ายใหม่ได้ก่อนส่ง |
| ย่อรูป (`preparePhotoForUpload`) | รูปหลาย MB ส่งช้า โดยเฉพาะในงานที่เน็ตไม่ดี |
| ไม่มีฟิลเตอร์ | รูปเป็นหลักฐาน การปรับสีทำให้ดูเหมือนแก้ไขรูป |
